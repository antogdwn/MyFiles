SECTION 2: ASP.NET Core / C# Fundamentals

Q1. What is the difference between .NET Framework, .NET Core, and .NET 5+?

.NET Framework is Windows-only, legacy. .NET Core (now unified as ".NET 5/6/7/8+") is cross-platform, open-source, higher performance, modular via NuGet, and is Microsoft's future direction.

Q2. Explain Dependency Injection and why ASP.NET Core has it built-in.

DI is a design pattern where a class receives its dependencies from outside rather than creating them itself, improving testability and loose coupling. ASP.NET Core has a built-in IoC container; services are registered in Program.cs/Startup.cs with lifetimes: Transient (new instance every time), Scoped (one per request), Singleton (one for app lifetime).

Q3. What is Middleware in ASP.NET Core? Give examples.

Middleware are components in the request pipeline that process HTTP requests/responses in sequence (e.g., UseAuthentication, UseAuthorization, UseRouting, custom logging/exception-handling middleware). Order matters — e.g., Authentication must run before Authorization.

Q4. What's the difference between IEnumerable, IQueryable, and List?

IEnumerable — in-memory iteration, deferred execution, LINQ-to-Objects. IQueryable — builds an expression tree, execution deferred until enumerated, translated to SQL when used with EF Core (so filtering happens in the database, not in memory). List<T> — concrete, in-memory collection.

Q5. Explain SOLID principles briefly (you list this on your resume).

  • Single Responsibility — a class should have one reason to change.
  • Open/Closed — open for extension, closed for modification.
  • Liskov Substitution — subtypes must be substitutable for their base types.
  • Interface Segregation — many small interfaces over one large one.
  • Dependency Inversion — depend on abstractions, not concretions (ties directly to DI).

Q6. What is the Repository Pattern and why use it?

Abstracts data-access logic behind an interface, so business logic doesn't depend directly on EF Core/SQL specifics — improves testability (can mock the repository) and centralizes query logic.

Q7. Explain async/await in C#. Why use it in Web APIs?

async/await allows non-blocking I/O — while waiting on a DB call or external API call, the thread is freed to serve other requests instead of blocking, improving scalability under load.

Q8. What is JWT Authentication and how does it work?

JSON Web Token — client authenticates once, server issues a signed token containing claims (user id, roles, expiry). Client sends the token in the Authorization: Bearer <token> header on subsequent requests; server validates the signature/expiry without needing a session store — stateless auth.

Q9. Difference between Authentication and Authorization?

Authentication = who are you (verifying identity). Authorization = what can you do (verifying permissions/roles) — you mention Role-Based Authorization on your resume, be ready to explain [Authorize(Roles = "Admin")] style attributes.

Q10. What are Design Patterns you've used besides Repository?

Be ready to mention: Singleton, Factory, Dependency Injection (itself a pattern), Unit of Work (often paired with Repository).

SECTION 3: Entity Framework Core / SQL Server

Q1. What is Entity Framework Core? Code-first vs Database-first?

EF Core is an ORM mapping C# objects to database tables. Code-first: define C# model classes, EF generates the schema/migrations. Database-first: scaffold C# classes from an existing database.

Q2. What are Migrations in EF Core?

Version-controlled, incremental changes to the database schema, generated from model changes (Add-Migration, Update-Database), keeping schema and code in sync across environments.

Q3. Explain LINQ. Give an example.

Language-Integrated Query — query syntax embedded in C# for collections/databases.

var activeUsers = dbContext.Users
    .Where(u => u.IsActive)
    .OrderBy(u => u.Name)
    .ToList();

Q4. What is N+1 query problem and how do you avoid it in EF Core?

Occurs when a query fetches a list, then a separate query runs per item to get related data (N extra queries). Fix with eager loading (.Include()), or projection (.Select()), to fetch everything in one query.

Q5. What are Stored Procedures and when would you prefer them over EF Core queries?

Precompiled SQL stored in the database. Prefer them for complex, performance-critical logic, batch operations, or when DBAs own query optimization — you mention writing/optimizing them on your resume.

Q6. What is CosmosDB, and how is it different from SQL Server?

CosmosDB is Microsoft's NoSQL, globally distributed database (document/key-value/graph models) — schema-flexible, horizontally scalable. SQL Server is relational, schema-enforced, ACID-transaction-strong. Use CosmosDB for high-scale, flexible-schema, low-latency global apps; SQL Server for strongly relational transactional systems.

Q7. How do you optimize a slow SQL query?

Check execution plan for table scans vs index seeks, add appropriate indexes, avoid SELECT *, avoid functions on indexed columns in WHERE clauses, consider query restructuring, check for missing statistics, consider pagination for large result sets.

SECTION 4: Angular (Gap area — study this carefully, even at a basic level)

Q1. What is Angular and how is it different from AngularJS?

Angular (2+) is a complete rewrite of AngularJS, using TypeScript, component-based architecture, and better performance via improved change detection — not backward-compatible with AngularJS (1.x).

Q2. Explain Components, Modules, and Services in Angular.

Component = UI building block (template + logic + styles). Module (NgModule) = groups related components/services/directives. Service = reusable business logic/data-access class, typically injected via Angular's DI system (@Injectable).

Q3. What is Data Binding in Angular? Name the types.

  • Interpolation: {{ value }}
  • Property binding: [property]="value"
  • Event binding: (click)="onClick()"
  • Two-way binding: [(ngModel)]="value"

Q4. What is a Service and what does @Injectable do?

A service is a class with reusable logic (e.g., calling a REST API). @Injectable() marks it eligible for Angular's DI system so it can be injected into components/other services.

Q5. How does Angular call REST APIs? (Ties directly to your REST API experience.)

Via HttpClient (from @angular/common/http), typically wrapped in a service:

this.http.get<User[]>('api/users').subscribe(data => this.users = data);

Q6. What is RxJS and Observables in Angular?

RxJS is a reactive programming library; Angular uses Observables (from RxJS) for async operations like HTTP calls, allowing operators like map, filter, switchMap to transform/compose async streams.

Q7. What is the difference between a Directive and a Component?

A Component is a directive with a template. Structural directives (*ngIf, *ngFor) change DOM structure; attribute directives (ngClass, ngStyle) change appearance/behavior of an existing element.

Q8. What is Dependency Injection in Angular?

Same concept as backend DI — Angular's injector provides service instances to components/services declaring them in the constructor, rather than each class instantiating its own dependencies.

Q9. What's new/notable in recent Angular versions (Angular 17+)?

Standalone components (no NgModule required), new control-flow syntax (@if, @for instead of *ngIf/*ngFor), Signals for reactive state management, and improved build performance (esbuild/Vite-based dev server). Honest framing: "My hands-on experience is primarily backend, but I understand these concepts and I'm actively building small Angular apps to strengthen this side — happy to walk through what I know."

Q10. How would you structure communication between a .NET Web API backend and an Angular frontend?

RESTful endpoints returning JSON, DTOs to avoid exposing EF entities directly, CORS configuration on the .NET side to allow the Angular origin, JWT-based auth passed via Authorization header, and Angular services wrapping HttpClient calls per feature.

SECTION 5: Microservices

Q1. What are Microservices and how do they differ from a Monolith?

Independent, loosely-coupled services, each owning a bounded business capability and its own data store, deployed/scaled independently — vs. a monolith where all functionality is a single deployable unit.

Q2. What challenges come with Microservices?

Inter-service communication complexity, distributed data consistency, more complex deployment/monitoring, network latency/failure handling, service discovery, and harder debugging across services.

Q3. How do microservices communicate?

Synchronous: REST/HTTP or gRPC. Asynchronous: message brokers like Kafka or RabbitMQ (mentioned as "good to have" in the JD) — decoupling services via events/queues.

Q4. What is an API Gateway?

A single entry point routing client requests to the appropriate microservice, often handling auth, rate limiting, and request aggregation — avoids clients needing to know every service's address.

Q5. How would you handle a failure in one microservice affecting others?

Circuit breaker pattern (e.g., Polly in .NET), retries with backoff, timeouts, and graceful degradation/fallback responses instead of cascading failures.

Q6. Relate your FedEx integration to microservices thinking.

Good talking point: centralizing shipping logic into one FedEx service is a microservices-style decomposition — a single, independently-updatable service consumed by four applications, rather than duplicated logic. Use this to bridge your real experience to the microservices question.
